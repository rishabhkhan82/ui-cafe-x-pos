Core principle

Step 1: AuthService exposes login state
// auth.service.ts (already exists, just ensure this exists)
private loggedIn = new BehaviorSubject<boolean>(false);
isLoggedIn$ = this.loggedIn.asObservable();

// Called after successful JWT storage
setLoggedIn(user: User): void {
  localStorage.setItem('user', JSON.stringify(user));
  this.loggedIn.next(true);
}

logout(): void {
  localStorage.removeItem('user');
  this.loggedIn.next(false);
}

getCurrentUser(): User | null {
  return localStorage.getItem('user') ? JSON.parse(localStorage.getItem('user')!) : null;
}
Step 2: AppComponent auto-connects on auth state change
// app.component.ts
export class AppComponent {
  constructor(
    private auth: AuthService,
    private realtime: RealtimeService
  ) {
    // Handle fresh login OR page refresh with existing session
    this.auth.isLoggedIn$.pipe(
      filter(isLoggedIn => isLoggedIn),
      take(1)  // only trigger once per login session
    ).subscribe(() => {
      const user = this.auth.getCurrentUser();
      if (user) {
        this.realtime.connect(user.id, user.restaurantId);
      }
    });

    // Optional: auto-disconnect on logout
    this.auth.isLoggedIn$.pipe(
      filter(isLoggedIn => !isLoggedIn),
      take(1)
    ).subscribe(() => {
      this.realtime.disconnect();
    });
  }
}
Step 3: AppComponent also handles page refresh recovery
On page refresh, AppComponent runs first. Check if session exists and auto-connect:

// In AppComponent constructor, BEFORE the isLoggedIn$ subscription
ngOnInit(): void {
  const existingUser = this.auth.getCurrentUser();
  if (existingUser) {
    // User refreshed page, session valid — reconnect immediately
    this.realtime.connect(existingUser.id, existingUser.restaurantId);
  }
  
  // Then listen for future logins
  this.auth.isLoggedIn$...
}
Step 4: RealtimeService connection guard
// realtime.service.ts
private isConnected = false;

connect(userId: string, restaurantId: string): void {
  if (this.isConnected) {
    this.disconnect();  // clean old connection first
  }
  
  this.socket = io(environment.apiUrl);
  this.socket.emit('authenticate', { userId, restaurantId });
  
  this.isConnected = true;
}

disconnect(): void {
  this.socket?.disconnect();
  this.isConnected = false;
}
Result
Scenario	What happens
First login	setLoggedIn() → isLoggedIn$ emits → AppComponent calls connect()
Page refresh	AppComponent ngOnInit sees localStorage user → auto connect()
Navigate to any page	Connection already live in singleton service — all pages work
Logout	isLoggedIn$ emits false → disconnect()
Close tab	Browser kills socket automatically
Where NOT to subscribe
Never in feature components (orders-mobile, customer-orders)
Never in navbar or notification bell
Those just read from the BehaviorSubject streams that AppComponent already populated
The complete ownership map
AppComponent
   ├── OnInit: checks localStorage → connect() if user exists
   ├── auth.isLoggedIn$ → connect() on login
   └── auth.isLoggedIn$ (false) → disconnect() on logout

RealtimeService (singleton)
   ├── socket.on('newOrder')      → newOrderSubject.next()
   ├── socket.on('newNotification') → newNotificationSubject.next()
   └── expose observables for whole app

Feature components (orders-mobile, customer-orders, bell)
   └── just subscribe to realtimeService.newOrder$
      or realtimeService.newNotification$
      (no connect/disconnect logic)
One subscription, all pages, auto-heals on refresh.
